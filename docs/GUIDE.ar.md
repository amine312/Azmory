# AZMORY v0.9

Dashboard محلية باش ترفع فيديو واحد وتختار الصفحات والحسابات اللي بغيتي ينزل فيها. النسخة فيها ربط OAuth ونشر عبر APIs ديال Meta وYouTube. التطبيق كيخدم من الحاسوب، وخصو يبقى شاعل حتى تكمل العمليات.

| المنصة | طريقة الربط |
| --- | --- |
| Facebook Reels | صفحة Facebook كتسيّرها، من خلال Facebook Login for Business |
| Instagram Reels | حساب Professional مرتبط بصفحة Facebook، من نفس الربط ديال Meta |
| YouTube Shorts | عدة قنوات، كل قناة كتربطها بوحدها عبر Google OAuth |
| TikTok | عدة حسابات عبر Buffer وCloudinary، حسب الخطة والصلاحيات |
| Threads | عبر Buffer وCloudinary |
| LinkedIn | بروفايل أو صفحة عبر Buffer وCloudinary |
| Bluesky | عبر Buffer وCloudinary، مع إيميل متحقق فـ Bluesky |

## 1. شغّل Dashboard على Windows

1. حمّل وثبّت **Node.js 24 LTS** من [nodejs.org](https://nodejs.org/).
2. فكّ الضغط على ZIP كامل، ودخل لمجلد `Azmory-0.9`.
3. دوبل كليك على `START-WINDOWS.cmd`. خلي نافذة CMD محلولة. إلا ما تفتحش المتصفح أوتوماتيكياً، لسّق فـ Chrome العنوان اللي كتبان قدّام Open in Chrome، افتراضياً [127.0.0.1:8787](http://127.0.0.1:8787).
4. فـ **الحسابات**، استعمل **Connect** باش تربط الحسابات اللي تفعّل ليها الربط.
5. فـ macOS أو Linux، شغّل `node server.mjs` من نفس المجلد.

إذا بان **في انتظار تفعيل الربط**، هادي مرحلة إعداد مدير التطبيق. إعداد المطوّر كيدار مرة وحدة فالسيرفر. من بعد، كل حساب كيتربط بالموافقة فصفحة المنصة.

## إلا ما تفتحش فـ Windows

- إلا بان **AZMORY v0.9 is running**، السيرفر راه شاعل. خَلّي CMD محلول وكتب العنوان اللي فيه فشريط العنوان ديال Chrome.
- إلا كتب **Port 8787 is already in use**، فتح العنوان فـ Chrome وشوف واش نسخة قديمة ديال ReelDesk باقية شاعلة. سدّ نافذة النسخة القديمة وعاود شغّل الجديدة.
- للتشغيل المباشر، حلّ المجلد اللي فيه `server.mjs` فـ File Explorer، كتب `cmd` فشريط مسار المجلد، ومن بعد نفّذ `node -v` و`node server.mjs` فـ CMD. استعمل العنوان اللي كيعطيك السيرفر فـ Chrome.

## نوع المنشور

من **منشور جديد → نوع المنشور** اختار **فيديو** أو **صورة** أو **نص فقط**. اللائحة كتبين الحسابات اللي تقدر تستعمل مع النوع المختار، وتقدر تنشر دابا أو تبرمج الوقت فالتقويم.

| النوع | المنصات |
| --- | --- |
| فيديو MP4 | Facebook وInstagram وYouTube وTikTok وThreads وLinkedIn وBluesky |
| صورة وحدة JPG أو PNG، حتى 8 MB | Facebook وThreads وLinkedIn وBluesky. Instagram كيتطلب JPG وCloudinary |
| نص فقط | Facebook وThreads وLinkedIn وBluesky |

- صور Bluesky خاصها تكون أقل من 1 MB. فـ Instagram استعمل JPG بنسبة بين 4:5 و1.91:1، مثلاً 1080 × 1080.
- النص اللي كتنشر هو **نص المنشور** أو النص المخصص للمنصة. العنوان الاختياري ديال الصورة والنص كيبان فالسجل والتقويم.
- صور وفيديوهات Buffer وصور Instagram كيحتاجو إعداد Cloudinary. منشور نصي عبر Buffer كيحتاج المفتاح ديال Buffer، ومنشورات Facebook المباشرة كتستعمل الربط ديال Meta.

## فحص قبل النشر

- اختار فيديو MP4. الفحص كيتدار محلياً وكيراجع الصيغة والحجم، ومن بعد كيبين المدة والأبعاد والوصف لكل منصة. تقدر تدوز هاد الخطوة قبل ربط الحسابات.
- استعمل **وصف خاص لكل منصة** إلا بغيتي تبدّل الوصف أو الهاشتاغات فشي شبكة. الخانات الخاوية كتستعمل الوصف المشترك.
- إذا كان بعض الحسابات المختارة كيدوزو الفحص وبعضهم ما كيدوزوش، كليكي **خلّي غير الحسابات الموافقة للفحص** وراجع الاختيار. تقدر حتى تبدّل الفيديو وتحتافظ بنفس الحسابات.
- نتيجة الفحص مبنية على القواعد المحلية ديال التطبيق. التأكيد ديال النشر كيبان من بعد فـ **سجل النشر**.

## إعداد مدير التطبيق

نسخ `.env.example` إلى `.env` فمجلد التطبيق. القيم اللي غادي تحتاجها لكل منصة مكتوبة لتحت. من بعد ما تضيفها، عاود شغّل AZMORY باش يتفعّل زر **Connect**. خَلّي `.env` و`.reeldesk-data` خاصّين عندك.

إلى كنت حافظ شي قيم فواجهة v0.4، AZMORY كيستعملها كبديل إلى كانت الخانة المقابلة فـ `.env` خاوية. القيم المعبّية فـ `.env` كتسبق القيم القديمة. إلى تبدّلات هوية OAuth ديال شي مزود، عاود الربط ديال داك المزود.

هاد الإصدار محلي لمالك واحد. باش تولّي الخدمة أونلاين لحسابات مستقلة، خص إصدار آخر بتسجيل الدخول، تخزين معزول لكل حساب، وسيرفر كيبقى شاعل للجدولة.

## 2. ربط YouTube

1. فـ [Google Cloud Console](https://console.cloud.google.com/)، اختار Project وفعّل **YouTube Data API v3**.
2. فـ **Google Auth Platform**، وجد معلومات الموافقة و**Audience**. إلا كان التطبيق فـ **Testing**، زِد الإيميل اللي كتدخل به للقناة فـ **Test users**.
3. خلق **OAuth client** من نوع **Desktop app**. حطّ **Client ID** و**Client Secret** فـ `GOOGLE_CLIENT_ID` و`GOOGLE_CLIENT_SECRET` فـ `.env`.
4. فـ **الحسابات**، كليكي **ربط قناة** قدّام YouTube واختار القناة المقصودة فصفحة Google. باش تزيد وحدة أخرى، كليكي **ربط قناة أخرى**. كل قناة كتبقى فاللائحة حتى تفصلها بوحدها. اختيار نفس القناة كيجدّد الربط ديالها.
5. فالتجربة الأولى اختار الخصوصية **خاص**. من بعد رفع الفيديو شوف النتيجة فالسجل وفتح الرابط أو [YouTube Studio](https://studio.youtube.com/).

التطبيق كيطلب صلاحية رفع الفيديو وصلاحية القراءة للتعرف على القناة والتحقق من حالة الرفع. Google يقدر يفرض قيود حسب وضع المشروع؛ راجع حالة الظهور الفعلية فـ YouTube Studio. فـ Testing، إلا سالا التفويض، عاود الربط.

[Google OAuth Desktop](https://developers.google.com/identity/protocols/oauth2/native-app) · [YouTube Data API](https://developers.google.com/youtube/data/reference/rest/v3/videos/insert) · [شروط Shorts](https://support.google.com/youtube/answer/15424877)

## 3. ربط Facebook وInstagram

1. حضّر Facebook Page عندك فيها صلاحية إنشاء المحتوى. إذا بغيتي Instagram، خاص الحساب يكون Business أو Creator ومربوط بهاد الصفحة.
2. فـ [Meta for Developers](https://developers.facebook.com/apps/)، وجد تطبيق **Business** فيه **Facebook Login for Business**. استعمل **Development** للتجربة بحساب عندو دور فالتطبيق وعندو الصلاحية فالصفحة.
3. وجد **Configuration** ديال Facebook Login for Business بنوع **User access token**، مع الأصول والصلاحيات حسب الحسابات اللي بغيتي:
   - Facebook — `pages_show_list` و`pages_read_engagement` و`pages_manage_posts`.
   - Instagram — `pages_show_list` و`pages_read_engagement` و`instagram_basic` و`instagram_content_publish`. بعض الأدوار الممنوحة من Business Manager تقدر تتطلب صلاحيات إضافية حسب Meta.
4. عنوان callback للتطوير هو `http://localhost:8787/oauth/meta`. راجع Web OAuth وlocalhost فإعدادات التطبيق وابقَ على Development للتجربة المحلية. إلى بدّلتي البورت، بدّلو فـ العنوان حتى هو.
5. حطّ **App ID** و**App Secret** و**Configuration ID** فـ `META_APP_ID` و`META_APP_SECRET` و`META_CONFIG_ID`. `META_GRAPH_VERSION` فيها v25.0 افتراضياً. استعمل النسخة اللي كيدعمها التطبيق ديالك إلى كان خاص تغيير.
6. فـ **الحسابات**، كليكي **Connect** قدّام Facebook أو Instagram. بجوج كيستعملو نفس نافذة الموافقة ديال Meta. وافق على الصفحات اللي بغيتي. أي صفحات وحسابات متاحة للنشر كيبانو فاللائحة بعد الربط.

Facebook كينشر فـ Pages. حساب Instagram خاصو يكون Professional. صلاحيات الحسابات التابعة لأشخاص خارج أدوار تطبيق التطوير كتقدر تحتاج Meta App Review. إلى رجّع Meta جواب ديال رفض الربط، راجع نوع Configuration، حساب الاختبار، صلاحيات الأصول، وcallback فـ Meta Dashboard.

[Meta Facebook Reels](https://www.postman.com/meta/facebook/folder/l0tw84j/reels-publishing) · [Instagram Content Publishing](https://developers.facebook.com/docs/instagram-platform/content-publishing/) · [Meta Instagram API](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api)

## 4. ربط حسابات Buffer

1. فـ [Buffer → Channels](https://publish.buffer.com/settings/channels) ربط TikTok أو Threads أو LinkedIn أو Bluesky. من Settings → API، خلق API key ديالك وانسخو فـ `BUFFER_API_KEY` فـ `.env`. إلا كان الربط ديال TikTok خدام عبر Buffer، استعمل نفس الإعداد.
2. فـ [Cloudinary Console](https://console.cloudinary.com/)، خذ Cloud name وAPI key وAPI secret ديال البيئة ديالك. عمّر `CLOUDINARY_CLOUD_NAME` و`CLOUDINARY_API_KEY` و`CLOUDINARY_API_SECRET` فـ `.env`.
3. فـ AZMORY مشي لـ **الحسابات** وكليكي **حدّث حسابات Buffer**. الحسابات المتاحة كيبانو فاختيارات النشر. عدد الحسابات مرتبط بالخطة ديال Buffer.
4. منين تختار حساب كيدوز من Buffer، أكّد إرسال النسخة المؤقتة. إلى اخترتي TikTok، حدّد وسم الذكاء الاصطناعي إلا كان كينطبق. باش تنشر الفيديو فـ Bluesky خاص الإيميل ديال الحساب يكون متحقق.
5. AZMORY كيخزن نسخة محمية فـ Cloudinary وكيعطي Buffer رابط موقّع كيصالي بعد ساعة. منين Buffer كيأكد النشر أو الفشل النهائي، AZMORY كيحاول يحيد النسخة المؤقتة. إلى بقى الطلب فانتظار، استعمل **حدّث الحالة** فالسجل إلا كانت متاحة، وراجع Buffer قبل إعادة الإرسال.

[Buffer API](https://support.buffer.com/articles/using-buffers-api-GtIYIQilz5) · [مواصفات الفيديو فـ Buffer](https://support.buffer.com/articles/sharing-videos-through-buffer-LOe2p2rnAI) · [Cloudinary](https://cloudinary.com/documentation/control_access_to_media)

## 5. تجربة النشر من بعد ما تكمل الربط

1. فـ CapCut صدّر MP4 عمودي 1080 × 1920، H.264 مع AAC و30 FPS. باش يوافق إعدادات هاد النسخة فالمنصات المختارة، استعمل فيديو من 4 حتى لـ 60 ثانية وحجمو حتى لـ 100 MB.
2. رفعو مرة وحدة، كتب العنوان والوصف، واختار حتى لـ 20 حساب فعملية وحدة. الفلتر حسب المنصة كيبدّل غير الحسابات اللي باينة فاللائحة وكيحتافظ بالاختيارات ديالك. فـ Instagram غادي يتحط الوصف كـ caption، وإذا كان خاوي غادي يستعمل العنوان.
3. بالنسبة لـ YouTube، اختار الخصوصية وواش الفيديو موجّه للأطفال. Facebook وInstagram كينشرو حسب إعدادات جمهور الحساب. اختار غير الحسابات اللي باغي تنشر فيها دابا، علّم على التأكيد، وكليكي على **نشر فالحسابات المختارة**.
4. للجدولة، بدّل **وقت النشر** من **دابا** لـ **برمج موعد**. اختار الوقت بتوقيت الجهاز، أكد، وكليكي **برمج النشر**. تقدر تبرمج حتى 10 فيديوهات للأيام الثلاثين الجاية، ومن **تقويم النشر** تقدر تتنقل بين الأسابيع، تبدّل موعد أي فيديو مبرمج بلا إعادة رفعه، أو تلغيه قبل الإرسال.
5. خلّي AZMORY والجهاز شاعلين وقت الموعد. إذا عاودتي تشغيل التطبيق من بعد الموعد، كيتسجل «فات الموعد» وخص برمجة جديدة. إذا وقف الجهاز مؤقتاً، الجدولة عندها سماح ديال دقيقة قبل تسجيل الموعد الفائت.
6. تابع **سجل النشر**. الحساب اللي كيوقع فيه خطأ كيبان بوحدو. إلا شفت «خاصك تتأكد» أو «تقبل الطلب»، راجع المنصة قبل إعادة الإرسال.
7. إذا بغيتي تعاود محاولة على حساب واحد، عاود اختار نفس الملف أو بدّل تفاصيل المنشور واختار غير الحساب المقصود. من بعد ما تكمل عمليات الإرسال، الملف المؤقت كيتحيد من التطبيق.

## التحقق والتحديثات

- **0.1** — ملف HTML مستقل للمعاينة، اختيار المنصات، وتجربة السجل.
- **0.2** — نفس Dashboard مع سيرفر محلي، OAuth، وإرسال الفيديو للوجهات المختارة.
- **0.3** — TikTok عبر Buffer مع نسخة فيديو محمية برابط مؤقت وحالة قابلة للتحديث.
- **0.4** — إعداد مفاتيح الربط من Dashboard ومعرفة حالة كل مزود.
- **0.5** — واجهة Connect وإعداد المطوّر فالسيرفر، وجدولة محلية مع سجل المواعيد.
- **0.5.1** — تحسين تشغيل Windows وإظهار العنوان وحالة السيرفر فـ CMD.
- **0.6** — اسم AZMORY فالواجهة، فحص محلي قبل النشر، ووصف خاص لكل منصة.
- **0.7** — Threads وLinkedIn وBluesky عبر Buffer، وتقويم أسبوعي مع تعديل الموعد بلا إعادة رفع الفيديو.
- **0.8** — ربط عدة قنوات YouTube، نشر فيديو واحد فعدة حسابات TikTok، وفلتر الحسابات حسب المنصة.
- **0.9** — منشورات بصورة أو نص فقط، معاينة الصورة، وجدولة الأنواع الثلاثة من التقويم.
- للترقية، سدّ النسخة القديمة وفكّ الضغط على v0.9 فمجلد جديد. إلى بغيتي تحتافظ بالربط والسجل، نسخ `.reeldesk-data` وملف `.env` إلا كان موجود من المجلد القديم للجديد.
- شغّل `npm test` باش تدوز الاختبارات الآلية. اختبارات النشر كتحاكي أجوبة المنصات. تجربة OAuth والنشر الفعلي خاصها إعداد تطبيقات Meta وGoogle، أو Buffer وCloudinary، والحسابات ديالك.
